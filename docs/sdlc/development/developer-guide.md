<!-- sdlc:auto:start overview -->
This is a two-app "notes app" generated by the Quorq AI SDLC platform: an approved React 19 + Vite single-page frontend (currently running on seeded sample data) and a FastAPI 0.115 backend that implements single-owner authentication and CRUD note endpoints. The backend persists to SQLite by default (via SQLAlchemy, with Alembic migrations) and can be pointed at PostgreSQL through DATABASE_URL; the frontend talks to the API through a small fetch wrapper that attaches a JWT bearer token and redirects to /login on 401s.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm/Vite, React 19 toolchain)
- Python 3.12 (per backend/Dockerfile)
- pip
- Docker and docker-compose (optional, for the Postgres service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd backend && pip install -r requirements.txt
3. (optional) docker-compose up -d to start the Postgres 16 db service; otherwise the backend defaults to a local SQLite file (app.db) with no setup
4. Set DATABASE_URL if using Postgres (e.g. pointing at the docker-compose db); otherwise skip
5. uvicorn app.main:app --reload (from backend/) to start the API on http://localhost:8000
6. In a new terminal: cd frontend && npm install
7. npm run dev to start the Vite dev server (defaults to calling the API at http://localhost:8000 via VITE_API_BASE_URL)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routers are thin: request handling lives in app/routers/*.py while persistence/business logic lives in app/services/*.py (see notes.py router delegating to services/notes.py)
- Every note/auth route (except /health, /auth/login) is guarded by the get_current_owner dependency, enforced at the router level via `dependencies=[Depends(get_current_owner)]`
- SQLAlchemy models use UUID primary keys and declarative Base from app/database.py; Pydantic schemas (app/schemas.py) define one Create/Update/Out set per entity
- Schema changes go through Alembic migrations under backend/migrations/versions, not app startup table creation
- Frontend screens live one-per-file under src/screens/, routed in App.tsx; shared UI/icon/brand primitives live in src/lib/ui.tsx, icons.tsx, brand.ts
- Frontend tests are co-located beside the code they cover (e.g. src/lib/api.test.ts, src/screens/Notes.test.tsx); Playwright e2e specs live separately under frontend/e2e/
- API base URL and auth token handling are centralized in frontend/src/lib/api.ts (VITE_API_BASE_URL, localStorage token, automatic redirect to /login on 401)
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend requests to the API fail with CORS errors | Set the backend's ALLOWED_ORIGINS environment variable to a comma-separated list including the frontend's origin; defaults only allow http://localhost:5173 and http://127.0.0.1:5173 |
| Password verification raises an error about bcrypt.__about__ | Ensure bcrypt stays pinned to 4.0.1 as in requirements.txt -- passlib's bcrypt backend is incompatible with bcrypt 4.1+ |
| `pytest` run from backend/ fails with `ModuleNotFoundError: app` | Run pytest from the backend/ directory where pytest.ini sets pythonpath = . so `import app` resolves |
| npm run build succeeds but deployment/typecheck fails | Run `npm run typecheck` (tsc --noEmit) separately, since `npm run build` does not typecheck |
| Playwright e2e tests fail to start | Run `npm run test:e2e:install` first to fetch the Chromium browser; without E2E_BASE_URL set, Playwright will also install backend deps and boot both API (port 8000) and frontend preview (port 4173) itself |
| Backend can't connect to a database | By default it uses a local SQLite file (sqlite:///./app.db), no setup needed; to use Postgres, run `docker-compose up -d` and set DATABASE_URL accordingly before starting uvicorn |
<!-- sdlc:auto:end troubleshooting -->
