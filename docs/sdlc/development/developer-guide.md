<!-- sdlc:auto:start overview -->
A single-owner notes app generated by the Quorq AI SDLC platform, built as two independently runnable apps in one repo: a FastAPI 0.115 backend (Python 3.12, SQLAlchemy 2 models, Alembic migrations, JWT auth) backed by SQLite by default (Postgres 16 in the approved architecture, via DATABASE_URL), and a Vite + React 19 SPA frontend using React Router, Tailwind CSS, and TipTap for rich text, that talks to the backend through a small typed fetch client. The backend implements real login/logout and notes CRUD (ownership-scoped, auth-gated); the frontend's screens were approved against seeded sample data and are wired to call the live API via src/lib/api.ts.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Python 3.12
- Node.js (for Vite 6 / npm)
- pip
- Docker and Docker Compose (optional, for Postgres via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd backend && pip install -r requirements.txt
3. (optional) docker-compose up -d db  # starts Postgres 16 on localhost:5432, user/db 'app'
4. Set DATABASE_URL to point at Postgres if not using the SQLite default (sqlite:///./app.db)
5. Set ALLOWED_ORIGINS to the frontend origin if not using the default dev origins (http://localhost:5173)
6. cd frontend && npm install
7. Set VITE_API_BASE_URL at build time if the backend isn't at the default http://localhost:8000
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routers are thin: request handling and auth/db dependencies live in app/routers/*, actual persistence and ownership scoping live in app/services/*
- Every notes/auth route depends on get_current_owner (JWT bearer auth) before reaching handler logic
- Pydantic schemas follow an *Create/*Update/*Out naming pattern per entity (NoteCreate, NoteUpdate, NoteOut)
- SQLAlchemy models use typed Mapped/mapped_column declarative style, with PostgreSQL-specific types applied via .with_variant for cross-dialect compatibility
- Schema changes go through Alembic migrations against DATABASE_URL; the app does not create tables on startup
- Frontend: one module per approved screen under src/screens/, shared component/icon vocabulary in src/lib/ui.tsx and src/lib/icons.tsx, brand tokens in src/lib/brand.ts and index.css
- Frontend API calls are centralized through apiFetch in src/lib/api.ts, which attaches the bearer token from localStorage and redirects to /login on 401
- Routes requiring auth are nested under a RequireAuth guard component in App.tsx
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend requests to the backend are blocked by CORS | Set the backend's ALLOWED_ORIGINS env var to a comma-separated list including the frontend's origin; defaults only allow http://localhost:5173 and http://127.0.0.1:5173 |
| App repeatedly redirects to /login | The stored session token is missing, expired, or rejected (401 from the API), which clears it and redirects; log in again via POST /auth/login |
| `pytest` run from the repo root fails to import app | Run pytest from backend/ (or rely on pytest.ini's pythonpath=. there) so `app` is importable |
| Backend won't start without a database server | No setup needed for local dev: DATABASE_URL defaults to sqlite:///./app.db; set DATABASE_URL to a Postgres connection string (e.g. after docker-compose up -d db) to use Postgres instead |
| `npm run build` succeeds but deployment/type errors appear | Run `npm run typecheck` (tsc --noEmit) separately, since build does not typecheck |
